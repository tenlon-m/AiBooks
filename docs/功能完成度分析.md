## 二、总体结论

| 判定 | 结论 |
|---|---|
| **代码占位标记** | 全 `src/` 搜索 `TODO\|FIXME\|NotImplementedError\|敬请期待\|待实现\|暂未实现`，仅命中 `src/ui/pages/base_page.py:22,25,28`（抽象基类，且 25 个页面**全部直接继承 QWidget，无一处继承 BasePage** → 死代码）。后端 api/services/ai/db 四层**零占位**。 |
| **"敬请期待"式空壳弹窗** | **0 处**。所有按钮要么真实调用后端，要么属于下述具体缺陷。 |
| **实测可用率** | 25 个页面共约 130 个交互入口，其中 **5 个 P0 缺陷**导致 4 项功能实际不可用（情感曲线生成、续写/扩写/缩写、AI 对话侧栏发送、撰写页保存正文）+ 1 个崩溃点（创建/删除项目）。其余均可用。 |
| **主要风险类型** | 不是"没写完"，而是**「后端已完整实现，前端调用契约写错」**——路径、请求体字段名、枚举取值、SSE 事件字段四类错配。这类问题静态看不出来，运行时才暴露。 |
| **次要风险类型** | 后端已实现但 UI 未开入口（批量再校验、章节合并拆分、章节衔接优化、物品管理、关系手动 CRUD）。 |

## 四、缺陷清单

### P0 — 功能实际不可用 / 数据丢失 / 崩溃

#### P0-1 情感曲线生成完全不可用

**影响**：辅助工具 → 情感曲线，「生成情感曲线」点击后必定失败。

**证据与成因**（四处错配）：

| # | 位置 | 现状 | 后端契约 |
|---|---|---|---|
| 1 | `emotion_curve_page.py:180` | `SsePostWorker("/api/emotion/analyze")` | `emotion_router.py:20` 只有 `POST /analyze/stream` → **404** |
| 2 | `emotion_curve_page.py:168-175` | payload `{project_id, range, user_ideas, start_chapter, end_chapter}` | `emotion_schema.py:18` `EmotionAnalyzeRequest{project_id, chapter_ids: list[str]}` → **422** |
| 3 | `emotion_curve_page.py:186-203` | 读 `status` / `completed_ratio` / `current_chapter` / `total_chapters` / `chapters` | `emotion_curve_service.py:93-124` 只 yield `EmotionStreamChunk{type: progress\|chunk\|done, chapter_id, point, message}` → 进度条与图表**永不更新** |
| 4 | `emotion_curve_page.py:141-161` | 读 `chapters[].chapter_label/tension/fluctuation` | `get_curve` 返回 `{project_id, points:[{point_id, project_id, chapter_id, chapter_no, tension, emotion_fluctuation}]}` → 刷新也**读不到数据** |
| 5 | `emotion_curve_page.py:213` | 生成成功后调 `_mark_unsaved()` | 语义错误：操作成功反而标脏 |

**修复方向**：路径改 `/api/emotion/analyze/stream`；前端先 `GET /api/writing/{pid}/chapters` 按范围筛出 `chapter_ids`；`_on_sse_event` 改按 `type` 分支（progress→进度文案 / chunk→累积 `point` 增量绘图 / done→结束或报错，需处理 `message`）；`_load_existing_curve` 改读 `points[]` 并用 `chapter_no` 生成标签；移除 `:213` 的错误 `_mark_unsaved()`。

### 9.3 打包回归：动态路由注册导致打包后全部接口 404

**现象**：源码运行一切正常；PyInstaller 打包成 exe 后运行，「AI源列表」等所有接口报 `API 404: Not Found`。

**根因**：8.5 把 `server.py` 的 34 处静态 `from src.api.routers import xxx_router` 重构为
`importlib.import_module(f"src.api.routers.{module_name}")` 后，PyInstaller 的**静态导入扫描再也看不到这些模块**，
它们不会被打进 exe；运行时 `import_module` 失败 → 路由未注册 → 该前缀下接口全部 404。
这是「8.5 静默失败治理」引入的回归，源码运行模式下无法暴露。

**修复**：
1. `aibooks.spec` 的 `hidden` 增加 `collect_submodules('src.api.routers')`（实测可枚举 35 个模块），并写明原因注释。
2. `server.py._register_routers` 增加注册结果汇总：全部成功记 INFO「34 个模块全部注册成功」；有失败则记 ERROR
   列出 `N/34 个模块未注册` 及对应前缀/tag。打包版 `console=False` 看不到控制台，这条日志落在 `data/logs`，是定位该类问题的第一现场。

**验证**：源码模式 `create_app()` → 34 个模块全部注册、189 条 API 路由；`pytest tests/ -q` → 185 passed。
打包模式需重新执行 `pyinstaller aibooks.spec` 后实测（已在 README 常见问题登记该症状与排查路径）。

**教训**（并入 8.6 第 1 项）：凡是 `importlib` / 动态导入，都必须同步在打包配置里显式声明，
否则「源码能跑、打包不能跑」，且因 `console=False` 而完全静默。 |
